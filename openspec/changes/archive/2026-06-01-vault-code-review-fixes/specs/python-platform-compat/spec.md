## ADDED Requirements

### Requirement: Python 3.7+ compatibility via __future__ annotations
Both `vault-context.py` and `scan-sessions.py` SHALL import `from __future__ import annotations` as their first non-comment import, enabling `Path | None` union syntax on Python 3.7+.

#### Scenario: No TypeError on Python 3.8 import
- **WHEN** `vault-context.py` or `scan-sessions.py` is imported on Python 3.8 or 3.9
- **THEN** no `TypeError` is raised at module load time due to `|` union syntax

#### Scenario: README documents minimum Python version
- **WHEN** a user reads the Requirements section of README.md
- **THEN** the minimum Python version is stated as 3.7+ (or 3.10+ if __future__ import is not added)

### Requirement: Plugin install detects correct Python executable on all platforms
The hook command generated by install scripts and by the plugin installer (Option A) SHALL use the Python executable that is actually available on the user's system.

#### Scenario: Windows plugin install uses available Python executable
- **WHEN** a Windows user installs the plugin via Option A (plugin marketplace)
- **THEN** the hook uses `python` or `py` if `python3` is not in PATH
- **THEN** `vault-context.py` runs successfully on Windows

#### Scenario: macOS/Linux install uses python3
- **WHEN** a macOS or Linux user installs the plugin
- **THEN** the hook uses `python3` as before

### Requirement: scan-sessions.py is copied to vault on plugin install
The plugin install path (Option A, via `install.sh` or plugin `onInstall` hook) SHALL copy `scan-sessions.py` to the vault's `scripts/` directory alongside `vault-context.py`.

#### Scenario: run_scan finds scan-sessions.py after plugin install
- **WHEN** a user installs via Option A and a new Claude session starts
- **THEN** `vault-context.py`'s `run_scan()` can locate `scan-sessions.py` in the vault scripts directory
- **THEN** auto-scan populates `pending.md` correctly

#### Scenario: Standalone install already works
- **WHEN** a user installs via `./install.sh` (Option B)
- **THEN** `scan-sessions.py` is already copied to the vault by the installer (no regression)

### Requirement: Repo hygiene — personal paths removed from git tracking
`.github/hooks/context-mode.json` and `.serena/project.yml` SHALL be untracked from git (git rm --cached), removing personal absolute paths from the public repository.

#### Scenario: Files absent from git ls-files after cleanup
- **WHEN** `git ls-files .github/hooks/context-mode.json .serena/project.yml` is run after the fix
- **THEN** both files return no output (untracked)

#### Scenario: Files still listed in .gitignore
- **WHEN** the files are untracked
- **THEN** they remain in `.gitignore` so future commits don't re-add them

### Requirement: .gitignore has no duplicate entries
`.gitignore` SHALL NOT contain the same pattern repeated more than once.

#### Scenario: No duplicate lines in .gitignore
- **WHEN** `.gitignore` content is inspected
- **THEN** no pattern appears more than once

### Requirement: Version strings aligned across all manifests
`plugin.json`, `marketplace.json`, and `__version__` in `vault-context.py` SHALL all reference the same version string.

#### Scenario: All version references match after fix
- **WHEN** `plugin.json`, `marketplace.json`, and `vault-context.py` are inspected
- **THEN** all three report the same version (1.0.0 or higher)
